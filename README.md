# DjedCall

غرف صوتية جماعية تعمل مباشرة في المتصفح عبر WebRTC، بدون خادم تطبيق أو قاعدة بيانات.
الواجهة ملفات ثابتة تُنشر على Cloudflare Pages، ويتصل المشاركون ببعضهم مباشرة،
بينما يُستخدم خادم PeerJS للتنسيق الأولي فقط.

## الغرض ونطاق الاستخدام

صُمم **DjedCall** كأداة صوتية سريعة وخفيفة للتواصل المباشر في الدوائر الموثوقة: **بين الأصدقاء، الأقارب، وفرق العمل**:
- **ليس للتواصل مع الغرباء**: لا يهدف التطبيق ليكون شبكة عامة أو منصة للتعارف؛ لا توجد غرف عامة، ولا دليل مستخدمين، ولا حسابات شخصية أو أدوار إشرافية.
- **مجموعات موثوقة فقط**: رمز الغرفة هو وسيلة الوصول الوحيدة؛ شارك الرابط مع من تعرفهم وتثق بهم فقط.
- **بساطة وخصوصية**: لا تسجيل، ولا تخزين، ولا إعلانات، والمكالمة مشفرة بالكامل وتنتهي تماماً بمجرد مغادرة أطرافها.

## المزايا

- **تأسيس فوري للمكالمات**: إطلاق اتصالات الصوت والبيانات بالتوازي لربط الأطراف خلال أقل من 3 ثوانٍ.
- **صوت نقي فائق السرعة**: كوديك Opus مضبوط بزمن استجابة منخفض (`latency: 0.01` وحزم 10-20ms) لمنع أي تأخير في بداية الكلمات.
- **محرك تجوال وتعافي تلقائي (Network Roaming)**: مراقبة حالة الشبكة وإعادة ربط أطراف الغرفة تلقائياً عند التبديل بين الواي فاي وبيانات الهاتف (WiFi ⟷ 4G) دون الحاجة لإعادة تحميل الصفحة.
- **كشف مسار الاتصال الفعلي**: شارة واضحة على بطاقة كل مشارك تبيّن طبيعة المسار: `محلي` (على نفس الراوتر)، أو `مباشر` (عبر الإنترنت)، أو `عبر خادم` (ترحيل TURN).
- **إلغاء الصدى والضوضاء**: معالجة برمجية تلقائية لتنقية الصوت ومؤشر VAD لكشف التحدث في الوقت الفعلي.
- **منع نوم الشاشة (Screen Wake Lock)**: إبقاء معالجات المتصفح نشطة أثناء المكالمات الصوتية على الهواتف لمنع تقطيع الصوت عند سكون الشاشة.
- **مزامنة فورية وتمييز الأعضاء**: تزامن تلقائي لحالة كتم المايك للأعضاء الجدد، وتمييز تلقائي للأسماء المتطابقة.
- **محادثة كتابية خفيفة**: شريط رسائل جانبي مشفر P2P مع إشعار بالرسائل غير المقروءة.
- **مشاهدة واستماع مشترك ليوتيوب (Watch & Listen Together)**: تشغيل متزامن لحظي للفيديوهات والموسيقى بالثانية الواحدة عبر WebRTC، مع وضعين: فيديو وصوت فقط، وجودة مستقلة لكل مستخدم (144p - 1080p)، وبحث مدمج مع مؤشر كتابة لحظي، وتعافي فوري عند التعليق أو انقطاع النت.
- **مراقب التواجد والانقطاع كل 5 ثوانٍ**: نبضات تحقق سريعة لكشف انقطاع الإنترنت الفعلي بدلاً من البقاء على حالة «متصل» كاذبة، مع استعادة الاتصال تلقائياً فور عودة الشبكة.
- **تخصيص الخوادم من المتصفح**: نافذة إعدادات مرنة تتيح استخدام خوادم التنسيق (Signaling) والترحيل (STUN/TURN) الخاصة بك دون تعديل الكود، مع ترويسات CSP آمنة.
- **استقلالية تامة**: واجهة عربية متجاوبة بدون أي طلبات خارجية أو تتبع أو خطوط من خوادم طرف ثالث.

## طريقة الاستخدام

1. افتح الموقع.
2. اكتب اسمك ورمز الغرفة، أو استخدم زر الرمز العشوائي.
3. اسمح بالوصول إلى المايكروفون.
4. شارك رابط الغرفة مع من تريد.

يُحفظ الاسم في المتصفح بعد أول استخدام، ويمكن تغييره لاحقاً من شريط الغرفة.

## كيف يعمل

1. يسجّل كل مشارك معرّفاً فريداً على خادم PeerJS.
2. يحجز أول مشارك في الغرفة معرّف البوابة، ويتولى تعريف الأعضاء الجدد ببقية المشاركين عبر تبادل قائمة الحضور (Roster).
3. يطلق العضو الجديد اتصال قناة البيانات ومكالمة الصوت بالتوازي (Parallel Setup) دون انتظار تسلسلي.
4. يختار ICE أفضل مسار لكل مشارك: مسار محلي مباشر host-to-host عبر الشبكة المحلية، أو مسار مباشر srflx عبر الإنترنت، أو مسار ترحيل relay عبر خادم TURN عند وجود جدران حماية مقيدة (CGNAT).
5. يستمع التطبيق لأحداث الشبكة وتغير واجهات الاتصال، ويقوم تلقائياً بتحديث مقابس الاتصال وإعادة وصل الأعضاء عند انقطاع مؤقت أو تجوال بين الشبكات.

## التشغيل محلياً

يتطلب Node.js 18 أو أحدث.

```sh
npx wrangler pages dev .
```

يشغّل Wrangler الموقع على منفذ محلي، ويحترم `_headers` و`_redirects`، لذا تعمل روابط الغرف المباشرة.

لمعاينة سريعة بدون Wrangler:

```sh
python3 -m http.server 8099
```

في هذه الحالة لا تعمل روابط الغرف عند إعادة التحميل، لأن الخادم لا يعيد توجيه المسارات إلى `index.html`.

## تخصيص الخوادم (من المتصفح مباشرة)

يمكن لأي مستخدم أو فريق استخدام بنيته التحتية الخاصة دون تعديل الكود:
1. اضغط على زر **«إعدادات الخوادم»** في واجهة الردهة الرئيسية.
2. أدخل نطاق خادم التنسيق (PeerJS) وخادم الترحيل (STUN/TURN) وبيانات الاعتماد الخاصة بك.
3. اضغط **«حفظ وتطبيق»**؛ تُحفظ هذه الإعدادات محلياً في متصفحك وتعمل تلقائياً.
4. يمكنك العودة للخوادم الافتراضية في أي لحظة بالضغط على زر **«استعادة الافتراضي»**.

## تشغيل الخوادم عبر Docker (Self-Hosting)

إذا أردت استضافة بنية تحتية خاصة بك بالكامل، يمكنك تشغيل كل من **خادم التنسيق (PeerJS)** و**خادم الترحيل (Coturn TURN/STUN)** باستخدام Docker.

### 1. تشغيل خادم التنسيق (PeerJS Server)

خادم PeerJS يتولى تنسيق الاتصال الأولي وتبادل معرفات الأجهزة (Signaling) عبر WebSocket:

```sh
docker run -d \
  --name peerjs-server \
  --restart always \
  -p 9000:9000 \
  peerjs/peerjs-server \
  --port 9000 \
  --path /
```

> **نصيحة أمان**: يُفضل وضع خادم PeerJS خلف بروكسي عكسي (مثل Caddy أو Nginx) لتوفير شهادة SSL/TLS ليعمل عبر المنفذ 443 و WSS المشفر.

### 2. تشغيل خادم الترحيل (Coturn STUN/TURN)

خادم Coturn يضمن عبور الصوت والبيانات عند الاتصال عبر شبكات المحمول (4G/5G) وجدران الحماية المقيدة (Symmetric NAT / CGNAT):

```sh
docker run -d \
  --name coturn \
  --restart always \
  --net=host \
  coturn/coturn \
  -n \
  --log-file=stdout \
  --listening-port=3478 \
  --fingerprint \
  --lt-cred-mech \
  --realm=your-domain.com \
  --user=djedcall:yourpassword \
  --external-ip=YOUR_SERVER_PUBLIC_IP \
  --min-port=49152 \
  --max-port=49250 \
  --user-quota=100 \
  --total-quota=200 \
  --denied-peer-ip=127.0.0.0-127.255.255.255
```

> **ملاحظات الإعداد**:
> - استبدل `YOUR_SERVER_PUBLIC_IP` بعنوان الآي بي العام لسيرفرك.
> - استبدل `yourpassword` و `your-domain.com` بالبيانات المناسبة لك.
> - تأكد من فتح المنفذ `3478` (TCP/UDP) ومجال منافذ الصوت `49152:49250` (UDP) في جدار الحماية (Firewall/UFW).

### 3. تشغيل الخادمين معاً عبر Docker Compose

يمكنك إنشاء ملف `docker-compose.yml` وتشغيل المنظومة بأكملها:

```yaml
version: '3.8'

services:
  peerjs:
    image: peerjs/peerjs-server:latest
    container_name: peerjs-server
    restart: always
    ports:
      - "9000:9000"
    command: ["--port", "9000", "--path", "/"]

  coturn:
    image: coturn/coturn:latest
    container_name: coturn
    restart: always
    network_mode: host
    command:
      - -n
      - --log-file=stdout
      - --listening-port=3478
      - --fingerprint
      - --lt-cred-mech
      - --realm=your-domain.com
      - --user=djedcall:yourpassword
      - --external-ip=YOUR_SERVER_PUBLIC_IP
      - --min-port=49152
      - --max-port=49250
      - --user-quota=100
      - --total-quota=200
      - --denied-peer-ip=127.0.0.0-127.255.255.255
```

شغّل الحاويات بأمر:
```sh
docker compose up -d
```

## النشر على Cloudflare Pages

### عبر Git

1. ارفع المشروع إلى مستودع Git.
2. أنشئ مشروعاً في Cloudflare Pages واربطه بالمستودع.
3. اترك أمر البناء فارغاً.
4. حدّد مجلد الإخراج ليكون جذر المشروع.
5. انشر.

تقرأ Cloudflare ملفي `_headers` و`_redirects` تلقائياً.

### عبر Wrangler

```sh
npx wrangler pages deploy . --project-name djedcall
```

## الأمان والخصوصية

- وسائط WebRTC مشفرة دائماً بـ DTLS-SRTP.
- لا يتم تسجيل الصوت ولا تخزين الرسائل على أي خادم.
- لا توجد حسابات ولا أدوار إدارية.
- تُنظّف الأسماء والرسائل، وتُفحص البيانات الواردة، وتُحدّد أحجامها ومعدلاتها لمنع الإغراق.
- رؤوس أمان صارمة عبر `_headers`، وكل الخطوط والأكواد مستضافة محلياً.

## حدود معروفة

- رمز الغرفة هو وسيلة الوصول الوحيدة؛ من يعرفه يمكنه الانضمام.
- الشبكة متكاملة، لذا يزداد الحمل مع عدد المشاركين. الأداء العملي الجيد حتى 6 إلى 8 مشاركين.
- تم دمج خادم STUN/TURN على نطاق المشروع عبر `ICE_SERVERS`، ويتم اللجوء للترحيل تلقائياً عند تعذر الاتصال المباشر بين الشبكات المقيدة (كالـ 4G/CGNAT).
- لا توجد هوية موثقة للمشاركين، فالاسم المستعار لا يُثبت هوية صاحبه.
- إشعارات المحادثة داخل التطبيق فقط.
